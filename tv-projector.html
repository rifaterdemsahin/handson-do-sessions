📺 TV Projector Automation

One keystroke opens the OBS Program fullscreen projector straight onto the Samsung TV — and moves it there if it is currently sitting on the MacBook display. No right-click menu hunting, ever.

1. The Problem and the Fix

On macOS, OBS numbers every connected display. Right-click → Fullscreen Projector → pick the TV works once, but it defaults to the MacBook display, it is buried three clicks deep, and the moment you change the display layout the choice goes stale.

  • The fix: a script (obs_tv_projector.py) that asks OBS which monitors exist, finds the Samsung by name, and tells OBS to open the Program projector fullscreen on that exact display over the OBS WebSocket API.
  • The trigger: ⌥+7, registered globally by the existing HUD agent (obs_indicator.py) so it works while any app has focus.
  • Why by name: macOS can reassign monitor indices when cables move. Matching "samsung" in the display name means the projector lands on the TV even when the index changes.
  • Moving an existing projector: the hotkey runs in --move mode — it closes any projector already open (wherever it is) and opens a fresh one on the TV.
🔀

2. How It Works

The script talks to the WebSocket server that OBS already runs for the HUD indicator (obs-websocket 5.7.4, port 4444, password from the same config file). Two requests do the whole job:

Step WebSocket request What it returns / does
1 GetMonitorList Every display with its OBS monitorIndex, name and resolution.
2 OpenVideoMixProjector Opens the PROGRAM mix fullscreen on the chosen monitorIndex.

Live output from this MacBook Pro, captured while writing this page:

Monitors as OBS sees them: 0 Built-in Retina Display(0) 1728x1117 at 0,0 1 SAMSUNG(1) 1920x1080 at -72,-1080 <-- TV TV match: SAMSUNG(1) (monitor index 1)
MacBook Pro (OBS UI) Samsung TV (HDMI) +------------------------------+ +------------------------------+ | monitor 0 | | monitor 1 | | Built-in Retina 1728x1117 | HDMI | SAMSUNG 1920x1080 | | OBS main window + preview | =======> | fullscreen PROGRAM projector | +------------------------------+ +------------------------------+

The manual equivalent inside OBS is right-clicking the Program preview and choosing Fullscreen Projector → SAMSUNG — the script simply performs that action through the API, on the right display, every time.

⚙️

3. One-Time Setup

Run these four commands from the repository root. They install the projector script next to the HUD agent, restart the agent so ⌥+7 is registered, and verify everything without touching OBS:

OBS_SCRIPTS="$HOME/Library/Application Support/obs-studio/scripts" # 1. Install the projector script + the updated hotkey agent cp obs-settings/scripts/obs_tv_projector.py "$OBS_SCRIPTS/obs_tv_projector.py" cp obs-settings/scripts/obs_indicator.py "$OBS_SCRIPTS/obs_indicator.py" # 2. Restart the HUD agent so Option+7 registers launchctl kickstart -k gui/$(id -u)/com.rifaterdemsahin.obs-indicator # 3. Verify: shows the monitors and which one is the TV /opt/homebrew/bin/python3 "$OBS_SCRIPTS/obs_tv_projector.py" --list # 4. Recommended: quit OBS first, then stop projectors from stacking /opt/homebrew/bin/python3 "$OBS_SCRIPTS/obs_tv_projector.py" --enable-close-existing
Step 4 requires OBS to be quit because OBS rewrites user.ini when it exits. It sets CloseExistingProjectors=true in the [BasicWindow] section, which makes OBS replace an existing projector on the same monitor instead of opening a second window on top of it — the difference between one clean projector and a pile of them after a few hotkey presses.

If the TV is ever renamed in macOS, pass a different hint: --name "bravia", or lock a fixed index with --monitor 1. Both flags work on every mode.

⌨️

4. Daily Use

During a session you only need the hotkey. The CLI modes exist for setup, testing and troubleshooting:

Command What it does
⌥+7 Move the program projector to the Samsung TV. Closes any open projector, then opens the Program feed fullscreen on the TV. HUD confirms with a 📺 pill.
--open Open a Program projector on the TV without touching existing windows (the default mode).
--move Close every open projector, then open one on the TV — what the hotkey runs.
--close Close every OBS projector window. Best effort via AppleScript; see the note below.
--list Show how OBS numbers the monitors and which one matched the TV.
--type preview Project the Preview mix instead of Program (also accepts multiview).
--monitor N Force an OBS monitor index when auto-detection is not what you want.
# typical session /opt/homebrew/bin/python3 "$OBS_SCRIPTS/obs_tv_projector.py" --move /opt/homebrew/bin/python3 "$OBS_SCRIPTS/obs_tv_projector.py" --list /opt/homebrew/bin/python3 "$OBS_SCRIPTS/obs_tv_projector.py" --close
🔁

5. Moving a Projector That Is Already Open

OBS's WebSocket API can open projectors but has no "close" request (verified against obs-websocket 5.7.4 — there is no CloseProjector and no projector hotkey). Closing is therefore done at the macOS layer:

  • Automatic: --move (and the hotkey) asks System Events to find windows whose name contains Projector, raise each one and press Esc — OBS closes a projector on Escape. It then opens the fresh projector on the TV.
  • One-time permission: the first automatic close needs Accessibility access. macOS shows nothing the first time; the script prints the exact hint. Grant it in System Settings → Privacy & Security → Accessibility for the Python that runs the agent (/opt/homebrew/bin/python3).
  • Manual fallback: click the stray projector window once and press Esc. With CloseExistingProjectors=true you only ever have to do this once — from then on the hotkey always lands on the TV.

Note what "move" means in practice: the projector is not dragged between displays. It is closed and re-created on the Samsung display, which is the only reliable way to retarget a fullscreen projector on macOS.

🛠️

6. Troubleshooting

Symptom Cause Fix
"Could not reach OBS on 127.0.0.1" OBS is not running, or its WebSocket server is disabled. Launch OBS → Tools → WebSocket Server Settings → enable the server on port 4444.
Projector opens on the MacBook screen Auto-detection missed the TV name, or you passed an index that no longer exists. Run --list, then use --monitor N or --name "samsung".
Two or more projector windows on the TV CloseExistingProjectors is not enabled yet. Quit OBS, run --enable-close-existing, relaunch OBS.
--close prints "macOS blocked UI scripting" Accessibility permission missing (error -25211). Grant Accessibility to /opt/homebrew/bin/python3, or press Esc on the projector window manually.
⌥+7 does nothing The HUD agent is running the old script. Re-run the install block in Section 3, then check ~/Library/Application Support/obs-studio/scripts/indicator.log.
TV went to sleep / input switched The display is off, so the projector draws to a black panel. Wake the TV on the correct HDMI input — macOS keeps the extended display alive.
🔬

7. Under the Hood

The exact request the script sends over the WebSocket (RPC version 1) for the captured layout above:

{ "op": 6, "d": { "requestType": "OpenVideoMixProjector", "requestId": "<uuid>", "requestData": { "videoMixType": "OBS_WEBSOCKET_VIDEO_MIX_TYPE_PROGRAM", "monitorIndex": 1 } } }

The password is read from plugin_config/obs-websocket/config.json — the same file the HUD indicator uses — and stays on the machine. Nothing is sent anywhere except 127.0.0.1. The script itself is in the repository at obs-settings/scripts/obs_tv_projector.py and is included in the OBS Settings Snapshot, so the whole studio — settings and this automation — rebuilds from one repo clone.

Verified on this machine: OBS Studio 32.2.2 with obs-websocket 5.7.4, capturing the built-in Retina display (monitor 0) and the SAMSUNG TV (monitor 1). OBS internals referenced: OpenVideoMixProjector in the obs-websocket protocol and CloseExistingProjectors in frontend/widgets/OBSBasic_Projectors.cpp. Companion pages: OBS Settings Snapshot and OBS Implementations & Scenes.
